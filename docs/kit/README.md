## दो रास्ते

विक्रम जी वहाँ **यह लिखें**:
```

पहले CLAUDE.md, फिर docs/सामान-इनबॉक्स/README.md पढ़ो और ठीक वैसे ही काम करो।
मैं रैक-वार सामान की फोटो भेज रहा हूँ — पहले सिर्फ़ जमा करो (scripts/foto.py), मेरे "अब काम करो" कहने पर
ध्यान से खेप बनाकर ऐप तक पहुँचाओ। मुझे "विक्रम जी" कहो, छोटे जवाब दो। बिलिंग मेरे कहे बिना कभी चालू मत करना।
```

### रास्ता B — सामान्य Claude ऐप (बिना GitHub) → ZIP → ऐप वाला Claude
1. विक्रम जी यह किट डाउनलोड करें: `docs/kit/mh177-saman-kit-v6.zip`

चालू न हो तो वह JSON टेक्स्ट देगा, और फोटो विक्रम जी को ऐप वाले Claude को दोबारा भेजनी होंगी।)

## 🤖 ऐप वाले Claude के लिए: ZIP आए तो
1. `git pull --rebase` → `python3 scripts/kit_import.py <zip> --dry` (देखो: ❌, ⚠, appId, सवाल)
2. ❌ हों तो stock.json सुधारो (फोटो देखकर), या विक्रम जी से पूछो। ⚠ "यह बारकोड ऐप में पहले से" आए तो कोई दिक्कत नहीं:
   ऐप बारकोड से मिलाकर सिर्फ़ खाली खाने भरता है।
3. `python3 scripts/kit_import.py <zip>`. यह असली फोटो फोटो-शाखा में push करता है, खेप बनाता है (web/data/items + web/p),
   कंपनियाँ (`docs/सामान-इनबॉक्स/companies.json`), सवाल (`sawal.md`) और पूरी जानकारी (`docs/सामान-इनबॉक्स/kaam/<batch>.json`:
   desc, geminiPrompt, ingredients — आगे ऑनलाइन दुकान के लिए) भी सँभालता है।
4. `node scripts/build.mjs` → `tests/packs.py` + e2e → commit/push (web/data, web/p, docs) → `python3 scripts/kit.py`
   (किट की 03/09/10 ताज़ा) → push।
5. विक्रम जी को 3–6 लाइन: "N सामान ऐप में भेजे (अपडेट दबाएँ), M कंपनी, K का बारकोड तैयार (बारकोड पहरा → रैक), सवाल: …"।

## ✅ ZIP चढ़ाते समय की जाँच-सूची (09/10-11-2026 की 6 ZIP से सीखा — हर बार यही क्रम)
1. `--dry` के बाद, असली चढ़ाने से **पहले** stock.json देखो (ZIP की नकल पर, `python3 -I`):
   - **वही सामान पहले से ऐप/खेप में, पर दूसरे खाने में** (बारकोड या दुकान-कोड 2000000… मिलाओ: `web/data/items/S-*.json` + `web/migrate.json`)
     → नया सामान मत बनाओ, रोको भी मत (विक्रम जी: "अलग खाने का अलग माल")। उसे ZIP की नकल से हटाकर अलग छोटी खेप बनाओ:
     `{"id":"<ऐप वाला id>","name":"…","xloc":{"6-15":10}}` (उदाहरण `web/data/items/S-20261110-01.json`) — स्टॉक में जुड़ता है + खाने-वार हिसाब।
   - **एक सामान ZIP में दो खानों में** (जैसे 8-13 में 4 + 8-14 में 4) → मुख्य खाने में उतनी ही गिनती रखो, बाकी के लिए xloc वाली खेप।
   - **नए खाने/रैक** (note में "7-14, 7-15 नए" जैसा) → `web/se-rack.js` की MAP में रैक के खाने बढ़ाओ, मिलाए गए खाने OLD में
     ("7-3":"7-2"), `tests/rack.py` की कुल गिनती और CLAUDE.md की "… खाने" वाली पंक्ति ठीक करो। रैक 9 में 9-34/9-35 = 9-6/9-7 के नीचे के बॉक्स।
   - **Buy 1 Get 1** → offer/packMrp/subtitle (docs/सामान-चढ़ाना-प्रॉम्प्ट.txt)।
2. खेप का नाम पहले से हो तो `kit_import.py` अपने-आप अगला नंबर देता है; एक कंपनी के दो id `docs/सामान-इनबॉक्स/company-alias.json` से
   अपने-आप पुराने id में (नया जोड़ा दिखे — जैसे Frutin's/Taparia — तो alias में जोड़ो, companies.json से दोहरा हटाओ)।
3. **चढ़ चुकी खेप की फ़ाइल बदलने से फोन तक कुछ नहीं जाता।** विक्रम जी के बाद के जवाब (रैक/MRP/गिनती) = नई छोटी "भरने वाली" खेप
   (वही id + सिर्फ़ वे खाने; उदाहरण `S-20261110-02.json`, `-05.json`); गिनती जोड़नी हो तो `xloc`; भरा हुआ मान बदलना = migrate.json `_upd` {from,to}।
4. `python3 scripts/pack.py check` → `python3 scripts/kit.py` → build → `tests/packs.py`, `tests/rack.py`, `tests/rkx.py`, `tests/org.py` + e2e → push → CI हरा देखो।
5. विक्रम जी को 3–6 लाइन: कितने सामान, कौन-से रैक, कितने बिना बारकोड (बारकोड पहरा), ⏰ जल्दी एक्सपायर वाले, और सिर्फ़ ज़रूरी सवाल
   (ZIP का सवाल.md + sawal.md)। जवाब आए तो sawal.md में "✅" लिखकर ऊपर के नियम 3 से भेजो।
6. बिलिंग "चालू" कभी अपने-आप नहीं; नए सामान की गिनती अपने-आप स्टॉक बनती है (SPK.autoStock)।
